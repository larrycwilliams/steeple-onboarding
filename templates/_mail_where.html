{# Open a Mail draft on the Mac the person is actually sitting at. The app runs on the hub, so mail_draft.create_draft opens Mail on the hub -- useless when Larry is travelling, which is most of the reason the tailnet exists. See claude/ops/29-where-mail-drafts-open.md. The browser is the way across. It is served by the hub but it is running on THIS Mac, so it can pull the message from the hub and hand it to a small local service (tools/draft_helper.py, 127.0.0.1:5055). The message crosses as data and becomes a real editable draft here. There used to be a second button here that opened a draft on the hub. It is gone: once the helper is installed on every Mac it did the same job worse, and it was the control that could quietly act on a machine nobody was sitting at -- the exact confusion that cost a session to diagnose. The route behind it still exists and still works; nothing links to it. Progressive enhancement: the page asks whether the helper is there and only then offers the button. Without it the screen falls back to Download .eml, which works from any Mac, and says how to install the helper. Included by the statement screen and the welcome-email screen. Both must set `eml_url` first. #}

{# The no-helper state, and what every Mac shows before the ping returns. #}
Drafts open on the Mac you are sitting at. This one is not set up for that yet, so use Download .eml — it is the complete message, and it works from any Mac. Open it, then Message ▸ Send Again (⇧⌘D) to turn it into a sendable copy; Mail shows an .eml as a received message until you do.
To get a real draft straight into Mail here, install the draft helper once — bash tools/install_draft_helper.command from the app folder. This page picks it up on its own afterwards.
